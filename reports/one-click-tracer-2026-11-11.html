Before, the home opened on Deployments, Stations and Oracle examples, and /models/, /routines/ and /parameters/ had no link on it. Now a Types section comes first, one tile per type in cards.domain.TYPE_ORDER (read from the data, so a new type shows up by itself), and Models · Routines · Parameters lead the Choose column and the header. Part 2 · The API

import sim2real

twin = sim2real.Twin.load("pendulum_can11")          # typed instances, parameters as robot_msgs Values
twin.simulate()                                      # MuJoCo, headless
fitted = twin.calibrate(on="sim", truth="sealed")    # a NEW twin: values_, intervals_, rungs_, calibration_
fitted.eval_twin().summary()                         # held-out runs only: error / floor and the gates

# the level below: fitted.runner (SimRunner: plan -> RealWorld.measure -> identify (sealed) -> score -> assemble)
# the mutation test of the ruler: twin.calibrate(on="sim", truth="sealed", move_truth={"can11.gravity_nm": 5.555})
# twin.calibrate(on="real") -> NotImplementedError naming the rack path

This follows the API prior-art note's verdict (vault: Sim2Real API Prior Art (2026-11-11)):

  • The verbs are on a sim2real Twin, not on the description. The description lives in robot_description, below sim2real, so verbs on it would bring back the cycle.
  • calibrate() returns a new fitted twin (scikit-learn style): learned values end in _, and nothing is written to robotparts.
  • eval_twin() refuses a training run. Identification runs sealed from the truth, and both guards live in the runner.
  • The fitting is sysid's existing oracle code, not mujoco.sysid. The pendulum's twin is bam_rack_twin's 30 kHz moteus PID with a gear-gap hinge (its Replayer), not a plain MJCF rollout. mujoco.sysid is in the pinned 3.11.0, but its extra's packages (colorama…) aren't installed. It's fit/'s engine for a type whose twin is plain MJCF.

What robot_description would need (a proposal; its contract is untouched here)

  • A typed instance element. Each component needs a name, its sim2real type id as a plain string, a parent, binds (joint, link) and parameters: Mapping[str, robot_msgs.space.Value]. Today Actuator and Sensor carry tags: tuple[tuple[str, str], ...], which hold strings, not Values with a unit and source.
  • A description of the station itself. The One Dof Test Rack's CAN 11 hinge and plate link aren't in it today (build_payload is the FB payload). The tracer's model is bam_rack_twin's MJCF, named by sysid's manifest.
  • A lowering that applies typed values. MJCF armature, damping and frictionloss should come from the instance's parameter Values, so a calibrated parameter set produces the twin's model.
  • Until then, sim2real.describe() is the thin adapter: it reads the sysid manifest and returns typed instances.
  • A contract gap, for the type card. integrated_servo has no parameter named gravity_bottom_rad or friction_stribeck_speed_rad_s. The oracle recovers both, and Instance.on_type carries and flags them.

Next for on="real"

  • Play the same schedule on CAN 11 through bam_rack_twin.hardware. Its torque cap and stops are the runner's guards, never callbacks.
  • Read the runs back through tools/run_files.py as robot_msgs JointTrajectory, then fit with the same identify.
  • Score held-out runs against the rack's own run-to-run floor (gate T1), not two camera draws.
  • Bind with binding=: the description stays address-free, and CAN ids and bus serials come from the deployment record.

The Twin's code

src/sim2real/twin.py, from class Twin on:

class Twin:
    """A description's twin: its typed instances, the model each runs (the type's current model unless `model=` picks a rung), and, once
    calibrated, its learned values (scikit-learn's convention: values_, intervals_, rungs_, calibration_ exist only on a fitted twin).
    Each verb is a thin call into its runner (self.runner), the level to drop to."""

    def __init__(self, description: Description, *, model: str | None = None, workers: int = 6):
        self.description = description
        self.runner = SimRunner(description, workers=workers)
        self.model = model or dm.current_models(self.runner.typed().type)[0].id

    @classmethod
    def load(cls, name: str, *, model: str | None = None, workers: int = 6) -> Twin:
        """A twin from its description's name (today the sysid oracle examples' manifests: sysid/examples/<name>/description.json)."""
        return cls(describe(name), model=model, workers=workers)

    @property
    def fitted(self) -> bool:
        return hasattr(self, "values_")

    def simulate(self, **options) -> Simulation:
        return self.runner.simulate(**options)

    def calibrate(self, on: str = "sim", *, truth: str = "sealed", move_truth: Mapping[str, float] | None = None) -> Twin:
        """A NEW twin, fitted: the type's routine schedule played `on` the simulator at the hidden truth (`truth="sealed"`: the fit never
        sees it) or on the real hardware. `move_truth` moves named hidden values for one run, the ruler unchanged (its mutation test)."""
        if on not in BACKENDS:
            raise ValueError(f"on must be one of {BACKENDS}, not {on!r}")
        if on == "real":
            raise NotImplementedError(
                "on='real' is next: the rack path. CAN 11 plays the same schedule on the One Dof Test Rack (bam_rack_twin.schedule replay "
                "through bam_rack_twin.hardware, its torque cap and stops as the runner's guards), its runs come back through "
                "tools/run_files.py as robot_msgs JointTrajectory, and the same identify fits them; held-out score against the rack's own "
                "floor (gate T1). Not wired in this lane.")
        if truth != "sealed":
            raise ValueError(f"on='sim' fits against a sealed hidden truth (truth='sealed'), not {truth!r}")
        calibration, state = self.runner.calibrate(model=self.model, truth=move_truth)
        fitted = Twin.__new__(Twin)
        fitted.description, fitted.model = self.description, self.model
        fitted.runner = SimRunner(self.description, workers=self.runner.workers, state=state)
        fitted.values_ = calibration.values
        fitted.intervals_ = {k: tuple(r["ci95"]) for k, r in ((r["name"], r) for r in calibration.rows) if r["ci95"]}
        fitted.rungs_ = calibration.rungs
        fitted.calibration_ = calibration
        return fitted

    def eval_twin(self) -> TwinReport:
        if not self.fitted:
            raise RuntimeError("eval_twin needs a fitted twin: fitted = twin.calibrate(...), then fitted.eval_twin()")
        return self.runner.eval_twin()

    def summary(self) -> str:
        return self.calibration_.summary() if self.fitted else self.description.summary()


def load(name: str, **options) -> Twin:
    """sim2real.load(name) is Twin.load(name): the brief's spelling, the same call."""
    return Twin.load(name, **options)
